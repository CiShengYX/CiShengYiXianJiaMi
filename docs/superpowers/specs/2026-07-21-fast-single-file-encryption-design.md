# CiShengYiXianJiaMi 高速单文件加密设计

日期：2026-07-21

## 1. 目标

在不改变五个现有节点名称和主要输入方式的前提下，重做生成内容的保存与加密链路：

- 图片、视频、文字、音频和普通文件都输出为一个可独立保存、传输和解密的 `.png` 文件。
- 文件必须写入 ComfyUI 的 `output` 目录，并由 ComfyUI 标准结果系统登记。
- 输出必须出现在节点结果、底部结果区域、执行历史和支持资产功能的左侧资产栏中。
- 用户通过标准图片右键保存时，得到完整的加密单文件，而不是封面缩略图或无效地址。
- 优先保证云端与本地环境中的速度、稳定性和低峰值内存；加密强度不是首要目标。
- 新生成文件使用新版格式；现有 V1 加密文件继续由解密页面读取。

## 2. 不在本次范围内

- 不承诺抵抗掌握代码和格式的专业逆向人员。
- 不修改 ComfyUI 核心文件，也不依赖某个云平台的绝对目录。
- 不新增工作流节点，不重命名已有节点，不改变工作流连接结构。
- 不把输出拆成预览图与加密载荷两个文件。
- 不保证所有 ComfyUI 历史版本都有左侧资产栏；在存在该功能的版本中使用标准登记机制。

## 3. 已选方案与备选方案

### 3.1 已选：PNG 外壳 + V2 分块 AES-GCM 载荷

保留合法 PNG 封面，在 PNG `IEND` 后追加带版本的分块加密数据。实际内容按固定大小分块加密并直接写入最终文件，避免构造完整明文、完整密文和拼接结果的多份内存副本。加密优先使用带本机加速的 `cryptography`，已有 `pycryptodome` 的环境也可直接使用；不再回退到极慢的纯 Python AES。

该方案同时满足单文件、正常右键保存、资产登记、错误密码检测、内容损坏检测和流式处理，是本次推荐方案。

### 3.2 未选：保留 V1，只优化界面与依赖

改动较小且完全保持生成格式，但 V1 是单个整体 AES-GCM 消息，难以做到真正的分块加密和网页端低峰值内存。它不能充分解决长视频和大文件的内存复制问题。

### 3.3 未选：XOR 等弱混淆

实现简单，但没有可靠的完整性检测，已知明文下容易恢复掩码。使用本机加速 AES 时，XOR 对整体耗时的改善很小，因为磁盘、视频编码和网络传输通常占主要时间。

## 4. 总体架构

实现划分为四个边界清晰的部分：

1. `encrypt_core.py`：定义 V1/V2 格式识别、密钥派生、分块加密、分块解密所需的纯数据接口。
2. `nodes.py`：负责将 ComfyUI 输入转换成可读取的数据源、调用加密器、原子保存文件并返回标准 UI 描述符。
3. `js/csyx_encrypt_preview.js`：只处理节点内的轻量封面展示和兼容性增强，不重复接管 ComfyUI 的标准资产、历史与下载逻辑。
4. `CiShengYX_decrypt.html`：识别 V1/V2；V2 按块读取并解密，批量任务顺序或限流执行，避免同时复制多个大文件。

加密核心不依赖 ComfyUI；节点层不实现密码学；前端预览不解析加密载荷；网页解密器不依赖云端路径。

## 5. V2 单文件格式

### 5.1 外层文件

- 文件扩展名保持 `.png`。
- 开头是经过校验的合法 PNG 封面，结束于标准 `IEND` 块。
- V2 数据包紧跟在 `IEND` 后。
- PNG 查看器和 ComfyUI 缩略图只显示封面；解密器读取尾部 V2 数据包。

### 5.2 V2 数据包

V2 数据包包含：

- 8 字节 CSYX 魔数。
- 1 字节版本号，值为 `2`。
- 内容类型：图片、视频、文字、音频或普通文件。
- 格式标志与保留字段。
- 元数据长度和规范化 UTF-8 JSON 元数据。
- 16 字节随机盐。
- 8 字节随机 nonce 前缀。
- 分块大小、原始长度和分块数量。
- 依次排列的加密块；每块记录明文长度、密文和 16 字节 GCM 标签。

默认明文块大小为 4 MiB。每块 nonce 为 8 字节随机前缀加 32 位块序号；同一文件中不得重复。元数据原始字节、内容类型、块序号和总长度作为认证附加数据参与每块校验。空内容也生成一个认证块。块数量和总长度必须一致，截断、调换、重复或篡改都必须报错。

元数据至少包含原始文件名、MIME 类型、原始字节数和创建格式版本。原始文件名必须经过净化，解密下载时不得形成目录穿越路径。

### 5.3 快速密钥派生

V2 使用带域分隔字符串、随机盐和 UTF-8 密码的 SHA-256 派生 256 位密钥，不执行高轮次 PBKDF2。这样可消除固定的密码拉伸耗时，代价是弱密码更容易被离线猜测。这个取舍符合“速度优先、无需重度防破解”的目标。

AES-GCM 仍提供内容保密和完整性检测。运行环境缺少 `cryptography` 时，节点必须在执行前给出明确的中文安装错误，不能静默进入纯 Python 慢速实现，也不能生成未加密文件。

## 6. 各节点数据流

### 6.1 图片加密

- 按批次逐张处理，不把整个批次复制成一个 NumPy 大数组。
- 每张图片编码为无损 PNG 数据源后立即分块加密并保存。
- 批量输入返回多个标准图片描述符，每个加密结果对应一个 `.png`。
- 图片编码使用兼顾速度和体积的压缩级别，不再固定使用最高压缩级别 9。

### 6.2 视频加密

- IMAGE 批次逐帧送入 FFmpeg，不先将全部帧转换成一份完整 NumPy 数组。
- FFmpeg 输出到安全临时 MP4；编码成功后从临时文件流式加密到最终 `.png`。
- 音频存在时继续合并；无音频时不创建无用音频临时文件。
- FFmpeg 失败、超时或退出码异常时保留清晰错误并清理临时文件，不留下伪成功输出。
- 视频编码耗时与加密耗时分开记录，便于判断瓶颈。

### 6.3 音频、文字和普通文件

- 音频先写临时 WAV，再从文件流式加密，不读回完整 `bytes`。
- 文字通过小型内存流处理。
- 普通文件直接从用户给定文件流读取，不一次性读入内存。
- 所有临时文件都放在系统或 ComfyUI 合法临时目录，并在成功或失败后清理。

### 6.4 原子保存

- 使用 ComfyUI `folder_paths` 获取输出目录与规范化保存位置。
- 先写同目录临时文件，完成全部加密和校验后再原子替换为最终文件。
- 执行失败不能留下被资产系统登记的半成品。
- 文件命名遵循 ComfyUI 的冲突规避逻辑，并保留用户提供的安全文件名前缀。

## 7. ComfyUI 展示与资产集成

每个节点返回标准 UI 字段：

```text
images: [{ filename, subfolder, type: "output" }]
```

这使当前 ComfyUI 能够：

- 在执行结果和历史中识别输出。
- 将文件登记到支持该功能的左侧资产栏。
- 使用标准 `/view` 路径展示结果。
- 使用标准右键保存得到完整加密文件。

为兼容已有前端扩展，过渡期同时返回结构一致的 `csyx_image`，但它不再是资产登记的唯一来源。前端必须对同一次执行去重，不同时通过节点 `onExecuted` 与全局 `executed` 事件重复添加预览。

节点画布内的自定义预览使用扩展自带封面资源，不请求完整载荷。标准底部结果和右键保存仍指向真实输出文件。由于右键保存要求浏览器持有完整单文件，标准结果第一次展示大文件时可能传输完整文件；这是单文件与原生右键保存共同带来的不可消除取舍。

前端扩展必须：

- 兼容有无新资产栏的 ComfyUI 版本。
- 对图片加载失败显示可恢复提示。
- 不在窗口重新获得焦点时销毁并重复创建全部图片。
- 正确清理事件监听器、对象 URL 和节点移除后的资源。
- 保持快捷菜单下载文件名为真实输出文件名。

## 8. 解密网页

- 自动定位 PNG `IEND` 后的数据，先判断 V2，再兼容读取 V1。
- V2 使用浏览器 Web Crypto 的 AES-GCM，按 4 MiB 块依次读取、校验和解密。
- 不再通过 `FileReader.readAsArrayBuffer` 并行加载所有选中文件。
- 批量解密默认逐个文件执行；单个文件内部逐块处理。
- 错误密码、文件截断、块标签错误、格式不支持和浏览器不支持 Web Crypto 都显示不同的中文错误。
- 单文件下载恢复原始文件名和类型。
- 批量 ZIP 仍可能受浏览器内存限制；页面需明确提示，并避免在未选择 ZIP 时长期保留所有已解密结果。
- V1 解密路径保持不变并加入回归样本，确保历史文件可用。

## 9. 依赖与环境兼容

- 新增 `requirements.txt` 声明 `cryptography`。
- 节点加载时只做能力检测；在真正执行加密时给出可操作的错误信息。
- 支持 Windows 与 Linux 路径规则，不拼接硬编码盘符或云端目录。
- FFmpeg 继续使用环境中可执行的 FFmpeg；找不到时明确提示安装或配置。
- 不修改 ComfyUI 核心，不覆盖全局 `/view` 路由。
- 保留现有节点类标识，旧工作流重新打开后无需替换节点。

## 10. 错误处理

- 加密依赖缺失：执行前终止，提示安装 `requirements.txt`，不使用慢速回退。
- FFmpeg 缺失或编码失败：报告命令阶段、退出信息摘要并清理临时文件。
- 输出目录不可写：报告目标目录类型，不暴露无关系统路径细节。
- 磁盘空间不足或写入中断：删除临时文件，不登记输出。
- 密码错误或载荷损坏：解密器不输出部分明文。
- 文件名异常：净化为安全名称；空名称使用现有默认前缀。
- 前端展示失败：不影响文件已经成功保存；提供重新加载和下载入口。

## 11. 验证方案与验收标准

### 11.1 格式和加密测试

- V2 对空内容、小于一块、刚好一块、跨多块和 100 MiB 数据往返一致。
- 图片、视频、文字、音频、任意文件五种内容类型往返一致。
- 中文、空格、长文件名和无扩展名能恢复为安全名称。
- 错误密码、修改任一密文字节、删除末尾、调换块顺序都必须失败。
- V1 固定样本继续能在新版解密网页中解密。
- 加密 `.png` 能被 Pillow 和浏览器当作封面 PNG 打开。

### 11.2 性能和资源测试

- 加密执行绝不调用纯 Python AES 后备实现。
- 普通文件、临时视频和临时音频的加密阶段按 4 MiB 分块，峰值额外内存不随文件总大小线性增长。
- 视频输入逐帧转换，不能创建覆盖整个批次的 `frames_np` 副本。
- 在带本机加速加密库和正常 SSD 的参考环境中，100 MiB 已编码文件的加密保存目标为 5 秒以内；环境差异导致的结果应单独记录。
- 几秒到十几秒的常见视频应主要受 FFmpeg 编码和网络影响，不再受 Python 加密实现拖慢。

### 11.3 ComfyUI 集成测试

- 五个节点的输出都位于 `output` 目录，并返回标准 `images` 描述符。
- 当前支持资产登记的 ComfyUI 中，输出出现在左侧资产栏。
- 输出出现在底部结果或历史结果区域。
- 右键保存得到的文件字节与 `output` 目录中的文件一致。
- 同一次执行不会出现重复预览。
- 节点折叠、复制、删除、刷新页面、切换标签页后不发生重复事件或失效预览。
- 未安装新资产栏的旧版 ComfyUI仍能执行、预览和保存。

### 11.4 本地可完成的验证与云端确认

本地完成格式、往返、损坏检测、Python 语法、JavaScript 语法、模拟 ComfyUI 输出结构和性能测试。最终左侧资产栏、底部结果区域以及不同云端镜像中的 FFmpeg/依赖行为，需要在真实 ComfyUI 环境做一次人工冒烟测试；本地测试不能虚假宣称覆盖云端界面。

## 12. 迁移策略

- 节点 ID、显示名称、输入字段和输出节点属性保持不变，现有工作流无需迁移。
- 新版本只生成 V2 文件。
- 解密网页同时读取 V1 与 V2，不批量重写用户已有加密文件。
- `csyx_image` 暂时保留一版作为前端兼容字段；标准 `images` 是后续唯一权威输出。
- 若安装依赖失败，升级后的节点明确停止并提示，不生成弱混淆或未加密的替代文件。

## 13. 完成定义

只有在代码测试通过、五类节点均返回标准描述符、V1/V2 解密通过、失败时无残留半成品，并在至少一个真实 ComfyUI 环境确认资产栏与右键保存后，才视为完整完成。若当前机器无法启动完整 ComfyUI，则交付时必须明确列出尚待云端验证的项目和最短验证步骤。
